# Known pitfalls

Read this before changing the catalog, the planner, the tests, the exercise dialog, the background or the secret scanner. Add a row when a fix teaches something that is not obvious from the code.

| Symptom | Cause | Fix |
| --- | --- | --- |
| A plan lists a movement that needs gear the user did not select, such as band pull-ups without a pull-up bar. | Each catalog entry could name only one piece of equipment, so a second requirement lived only in the description. | `equipment` is a list of everything the movement needs and the planner requires every item. Bodyweight movements have an empty list. When you add a movement, read its description for a bench, bar or band and list each one. |
| A catalog entry never shows up in any plan. | Its equipment or focus area was spelled in a way the form does not offer, and plain `string` fields let that through. | The form, catalog, planner and tests all read the lists in `src/data/options.ts`, and the catalog fields are typed from them, so a value that is not an option fails the typecheck. Add the option there first. |
| `npm test` fails with a module-not-found error after a change under `src/lib` or `src/data`. | Node runs `tests/planner.test.ts` and the files it imports directly, with types stripped and no bundler. It does not know the `@/` alias and does not add file extensions. | In files the tests import, write run-time imports as relative paths ending in `.ts`. Type-only imports are erased and can stay as they are. |
| A hold such as the plank is prescribed as a number of reps. | One prescription per goal was copied onto every exercise. | Each catalog entry has a `unit`, and the planner keeps a reps prescription and a seconds prescription for each goal. Mark every new hold as `seconds`. |
| Sessions come out much shorter than the length picked, and 45 and 60 minutes give the same day. | The pool for an area, gear and level is smaller than the session. Beginner bodyweight has one push movement and two each for pull and core. Moving spare time between a day's areas fixes almost none of these days. | The planner adds sets up to a limit, and every day carries its real length and a flag for when it is short, which the plan view shows. Only more catalog entries make those days longer, so check the thin pools before tuning the planner. |
| A session takes longer than the length picked. | Session size was a flat 5 minutes an exercise, whatever the goal's sets and rest. | The time for an exercise is worked out from its prescription in `exerciseSeconds`. If you change sets, reps, holds or rest, the number of exercises per session follows, and the tests that state the time model in their own words will tell you if the two drift apart. |
| The tests pass while plans are short, need missing gear or show holds as reps. | The combination test tried 4 of 64 gear sets and one goal, and its limits were loose enough to accept the faults. | `tests/planner.test.ts` now builds a plan for every setting the form can send and checks each promise exactly, using the lists in `src/data/options.ts`, so a new option joins the sweep by itself. A new promise belongs in `checkPlan`. To prove a check works, break the planner on purpose and watch it fail. |
| A closed dialog shows on the page. | A display class such as `flex` on the `dialog` element outranks the browser's own rule that hides a closed dialog. | Give the dialog its layout with the `open:` variant (`open:flex`), so it applies only while the dialog is open. |
| A click inside the exercise dialog closes it. | The browser reports a click on the backdrop as a click on the `dialog` element, and it reports a click on the dialog's own padding the same way. | The dialog has no padding and one child that fills it, and the click handler closes only when the target is the dialog itself. Keep padding and scrolling on the child. |
| `outline-none` on an element stops working, or a focus ring is missing. | The focus ring is one `:focus-visible` rule in `src/index.css`. It sits in Tailwind's base layer so utility classes can still override it. Moved out of the layer, it beats `outline-none`. | Leave the rule inside `@layer base`. Do not add ring classes to single buttons. |
| An entrance animation such as `animate-in fade-in` or `zoom-in-95` never plays. | Those class names belong to the tailwindcss-animate plugin, which is not installed. Tailwind writes no CSS for a class it does not know and gives no warning. | Use the `fade-in` animation from `tailwind.config.js` behind `motion-safe:`. After adding an animation class, build and search the CSS in `dist/assets` for it. |
| The background restarts or flashes when the pause button, the dialog or a resize touches it. | The loop, its particles and the canvas size live inside one effect. Anything added to that effect's dependencies rebuilds all of it. | `paused` reaches the loop through a ref and a second effect. A resize is applied once after it settles, keeps the particles, and ignores a small change in height alone, which is a phone toolbar sliding. |
| The background runs faster on some screens. | One step per animation frame doubles the speed on a 120 Hz display. | Steps follow the clock (`STEP_MS` in `flow-field-background.tsx`), 60 a second on any display. Keep new motion inside `step` so it is covered. |
| A bookmarked plan link opens a different week, or opens the form. | The link holds the settings and a seed, and the week is rebuilt from the catalog each time. Adding, removing or reordering catalog entries, changing how the planner draws random numbers, or changing `seeded` gives old links a different week. Renaming or removing an option in `src/data/options.ts`, or a key in `src/lib/plan-link.ts`, makes old links unreadable, and they open the form. | Treat option names and link keys as a published format. Adding an option is safe. A catalog change is fine, but it changes the weeks behind existing links. |
| Lint fails with `react-hooks/set-state-in-effect` when the page reads the address on load. | Setting state from an effect on mount also shows the form for one frame before the plan. | The link is read in a `useState` initialiser in `App.tsx`. Only the `hashchange` listener, which runs later, sets state. |
| The secret scan reports clean for `DB_PASSWORD="..."`, `myApiKey: "..."` or an unquoted `API_KEY=value`. | `\b` before a keyword cannot match after an underscore or inside camelCase, and the rule asked for quotes. | The generic rule in `.githooks/scan-secrets.py` allows a prefix and a suffix around the secret word and has an unquoted branch. Every shape is a row in `tests/test_secret_scanner.py`; add a row before changing the rule. |
| The secret scan blocks a commit of ordinary code, such as `token = getToken()` or a lockfile entry for a package with `token` in its name. | Once the generic rule accepts unquoted values and any name around the secret word, code and version numbers look like assignments. | `assignment_is_secret` filters placeholders, version ranges and dotted references, and asks for a digit in unquoted values. Put the false positive in `HARMLESS_LINES` in the tests, then adjust the filter. After any rule change, run the rules over every blob in history as well as `npm run scan:secrets`. |
| The secret scanner or its tests flag the scanner's own files. | A comment or fixture spelled out a credential shape, such as an address with a user and password in it. | Describe shapes in words in comments. In tests, join fixtures from fragments and random characters at run time. |
| A staged file is not scanned: one that replaced a symlink, or one named like `0:notes.txt`. | `--diff-filter=ACMR` leaves out type changes, and `git show :<path>` reads `:0:notes.txt` as stage 0 of `notes.txt`. | Hook mode lists staged blobs with `git diff --cached --raw --diff-filter=d` and reads each by blob id. |
| A UTF-16 file, or a text file with one stray NUL byte, passes the scan with a secret in it. | A NUL byte in the first 8000 bytes marked the file as binary and skipped it. | The scanner decodes files that start with a UTF-16 or UTF-32 byte order mark, removes NUL bytes from everything else and searches the result. It never skips a file; it names the ones that look binary. |
| `npm test` warns that the pre-commit secret scan is not active. | Git hooks are switched on by the `prepare` script. It does not run with `--ignore-scripts`, in a ZIP download or without git, and it refuses to replace another hooks setting or hooks in `.git/hooks`. | Read the warning: it names the cause. `npm run prepare` switches the hook on where that is safe. |
| A `className` passed to `PremiumButton` does not change its padding or text size. | `cn` in `src/lib/utils.ts` joins class names and does not settle conflicts, so two padding classes both reach the element and the stylesheet's order picks the winner. | Pick one of the button's `size` values, or add a size in `premium-ui.tsx`. Pass `className` only for things the component does not already set. |
| A link to the site shows no image when pasted into a chat, or shows an old one. | Link previews need full addresses, and only files in `public/` are deployed as they are. The preview services also keep their own copy of the image for days. | `index.html` builds the addresses from `%VITE_SITE_URL%`, which `vite.config.ts` fills from `homepage` in `package.json`. Keep `social-preview.png` in `public/`, and after replacing it ask each service's preview checker to fetch it again. |
| Text added to `index.html`, such as the note for visitors without JavaScript, shows unstyled or the browser console reports a blocked style. | The Content-Security-Policy in `vercel.json` allows neither a `style` attribute nor a `<style>` block. | Style it with Tailwind classes. `index.html` is in Tailwind's `content` list, so classes used there are built into the stylesheet. |
| The footer's source link, or the address in a link preview, points at the wrong place in a fork or after a rename. | Both addresses are read at build time from `repository.url` and `homepage` in `package.json` (`vite.config.ts`). Nothing else in the code holds them, and a test fails if `src/App.tsx`, `index.html` or `vite.config.ts` spells one out. | Change `package.json` and rebuild. A fork that serves a changed copy has to point `repository.url` at its own source to meet the licence. |
| `npm audit` reports a moderate minimatch advisory under `@typescript-eslint/typescript-estree` again, or `npm install` warns about the `overrides` entry. | typescript-eslint asks for minimatch 10, which has the advisory, and no release of it asks for 11 yet. `package.json` forces 11 for that one package through `overrides`. | Keep the override until `npm view @typescript-eslint/typescript-estree dependencies.minimatch` shows a range that includes 11.0.1, then delete it and run `npm install`. After any change to it, run `npm ls minimatch`, `npm audit` and `npm run lint`. |
| A wrong type in a test file, such as a misspelled plan setting, passes `npm test`. | Node runs the `.ts` test files by stripping the types without checking them. | `tsconfig.test.json` puts `tests/` under `tsc -b`, which `npm run build` and the full check run. Keep it in the `references` list of `tsconfig.json`. |
| A new test file passes locally and never runs in CI, or the reverse. | The files are listed by name in the `test:node` script. | CI runs `npm test`, so `package.json` is the only list. Add the new file to `test:node`. |
