# Known pitfalls

Read this before changing the catalog, the planner, the tests, the exercise dialog or the background. Add a row when a fix teaches something that is not obvious from the code.

| Symptom | Cause | Fix |
| --- | --- | --- |
| A plan lists a movement that needs gear the user did not select, such as band pull-ups without a pull-up bar. | Each catalog entry could name only one piece of equipment, so a second requirement lived only in the description. | `equipment` is a list of everything the movement needs and the planner requires every item. Bodyweight movements have an empty list. When you add a movement, read its description for a bench, bar or band and list each one. |
| A catalog entry never shows up in any plan. | Its equipment or focus area was spelled in a way the form does not offer, and plain `string` fields let that through. | The form, catalog, planner and tests all read the lists in `src/data/options.ts`, and the catalog fields are typed from them, so a value that is not an option fails the typecheck. Add the option there first. |
| `npm test` fails with a module-not-found error after a change under `src/lib` or `src/data`. | Node runs `tests/planner.test.ts` and the files it imports directly, with types stripped and no bundler. It does not know the `@/` alias and does not add file extensions. | In files the tests import, write run-time imports as relative paths ending in `.ts`. Type-only imports are erased and can stay as they are. |
| A hold such as the plank is prescribed as a number of reps. | One prescription per goal was copied onto every exercise. | Each catalog entry has a `unit`, and the planner keeps a reps prescription and a seconds prescription for each goal. Mark every new hold as `seconds`. |
| Sessions come out much shorter than the length picked, and 45 and 60 minutes give the same day. | The pool for an area, gear and level is smaller than the session. Beginner bodyweight has one push movement and two each for pull and core. Moving spare time between a day's areas fixes almost none of these days. | The planner adds sets up to a limit, and every day carries its real length and a flag for when it is short, which the plan view shows. Only more catalog entries make those days longer, so check the thin pools before tuning the planner. |
| A session takes longer than the length picked. | Session size was a flat 5 minutes an exercise, whatever the goal's sets and rest. | The time for an exercise is worked out from its prescription in `exerciseSeconds`. If you change sets, reps, holds or rest, the number of exercises per session follows, and the tests that state the time model in their own words will tell you if the two drift apart. |
| The tests pass while plans are short, need missing gear or show holds as reps. | The combination test tried 4 of 64 gear sets and one goal, and its limits were loose enough to accept the faults. | `tests/planner.test.ts` now builds a plan for every setting the form can send and checks each promise exactly, using the lists in `src/data/options.ts`, so a new option joins the sweep by itself. A new promise belongs in `checkPlan`. To prove a check works, break the planner on purpose and watch it fail. |
| A closed dialog shows on the page. | A display class such as `flex` on the `dialog` element outranks the browser's own rule that hides a closed dialog. | Give the dialog its layout with the `open:` variant (`open:flex`), so it applies only while the dialog is open. |
| A click inside the exercise dialog closes it. | The browser reports a click on the backdrop as a click on the `dialog` element, and it reports a click on the dialog's own padding the same way. | The dialog has no padding and one child that fills it, and the click handler closes only when the target is the dialog itself. Keep padding and scrolling on the child. |
| `outline-none` on an element stops working, or a focus ring is missing. | The focus ring is one `:focus-visible` rule in `src/index.css`. It sits in Tailwind's base layer so utility classes can still override it. Moved out of the layer, it beats `outline-none`. | Leave the rule inside `@layer base`. Do not add ring classes to single buttons. |
| An entrance animation such as `animate-in fade-in` or `zoom-in-95` never plays. | Those class names belong to the tailwindcss-animate plugin, which is not installed. Tailwind writes no CSS for a class it does not know and gives no warning. | Use the `fade-in` animation from `tailwind.config.js` behind `motion-safe:`. After adding an animation class, build and search the CSS in `dist/assets` for it. |
| The background restarts or flashes when the pause button, the dialog or a resize touches it. | The loop, its particles and the canvas size live inside one effect. Anything added to that effect's dependencies rebuilds all of it. | `paused` reaches the loop through a ref and a second effect. A resize is applied once after it settles, keeps the particles, and ignores a small change in height alone, which is a phone toolbar sliding. |
| The background runs faster on some screens. | One step per animation frame doubles the speed on a 120 Hz display. | Steps follow the clock (`STEP_MS` in `flow-field-background.tsx`), 60 a second on any display. Keep new motion inside `step` so it is covered. |
